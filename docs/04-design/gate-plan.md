## 2. 이번 단계에서 한 일

- 흔히 쓰는 방법 목록에서 먼저 후보를 2개 이상 찾기 — 서버가 있는 웹 / 화면 하나짜리 웹 / 표 계산 도구
- 후보끼리 좋은 점과 아쉬운 점 비교하기 — 서버가 있는 웹: 열쇠를 숨기고 AI·지도를 이어 쓰기 좋아요 · 화면까지 만들 게 늘어요 / 파이썬 프로그램: 날짜 넣고 리포트 받기까지 가장 빨라요 · 글자 창이라 보기엔 소박해요 / 휴대폰 앱: 여행 중에 꺼내 봐요 · 만들고 올리기 번거로워요
- 고른 방법과 왜 골랐는지 한 줄을 기록으로 남기기 — 고른 방법: 서버가 있는 웹 — 까닭: 날짜만 넣으면 AI와 지도 서비스를 뒤에서 이어 부르고, 열쇠도 안전하게 숨길 수 있어서요
- 지키기로 한 원칙(쓸 도구, 하면 안 되는 것, 화면 원칙)과 고른 방법 맞대어 보기 — 쓸 도구: 맞음 — AI와 지도 서비스를 이어 쓸 수 있어요 / 하면 안 되는 것: 맞음 — 날짜 말고 다른 개인 정보는 받지 않아요 / 화면 원칙: 아직 모름
- 누가 무엇을 볼 수 있는지, 정보를 어디에 둘지도 비교에 넣기 — 누가 무엇을 보나: 사용자 본인이 자기 리포트만 봐요 · 정보를 둘 곳: 서버(날짜와 추천 지역은 AI·지도 서비스로 나가요) · 들어올 때 확인: 불필요

## 5. 공부할 말

- Walking Skeleton — 꾸미기 전에 처음부터 끝까지 이어지기만 하는 가장 단순한 모양이에요
- 스모크 테스트 — 켜 보고 바로 멈추거나 깨지지 않는지 먼저 보는 짧은 확인이에요
- 작업 분해 — 큰 일을 하나씩 끝낼 수 있는 작은 일로 나누는 것이에요
- 보안 점검 — 비밀값 검사 — 비밀번호나 열쇠 같은 값이 코드나 기록에 남지 않았는지 찾아보는 일이에요
- 표준 카탈로그(아키텍처 5대 스타일) — 앱의 짜임새로 흔히 쓰는 방법들을 모아 둔 목록이에요
- 트레이드오프(ATAM 비교표) — 후보마다 얻는 것과 내주는 것을 한 표에 나란히 놓고 비교하는 거예요
- ADR — 무엇을 왜 골랐는지 남겨 두는 짧은 기록이에요
- 원칙표 점검·화면 원칙 — 미리 정한 약속(쓸 도구, 하면 안 되는 것)에 고른 방법이 맞는지 보는 일이에요
- 보안 점검 — 위협·권한·인증·저장 위치 — 누가 무엇을 볼 수 있는지, 정보를 어디에 둘지 미리 따져 보는 일이에요

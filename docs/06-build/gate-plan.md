## 2. 이번 단계에서 한 일

- 확인 방법을 먼저 정하고 만들기 — 날짜로 지역 추천 — 여행 날짜를 넣으면 가기 좋은 지역이 나와야 해요 / 맛집 찾기 — 그 지역을 넣으면 지도 서비스의 맛집이 나와야 해요 / 리포트 만들기 — 추천과 맛집이 모이면 1일 일정 리포트가 나와야 해요
- 작은 부분마다 확인 통과하기 — 날짜 입력 화면 — 날짜를 넣을 수 있어요 / 빈칸이면 안내가 나와요 / AI 지역 추천 — 지역 이름이 나와요 / 지도 맛집 찾기 — 맛집이 하나 이상 나와요 / 리포트 — 추천·맛집·1일 일정이 모두 들어 있어요
- 쓰는 사람 입장의 시나리오대로 돌려 보기 — ① 사용자가 여행 날짜를 넣고 버튼을 눌러요 → ② 앱이 가기 좋은 지역을 추천하고 그 지역 맛집을 찾아요 → 결과: 추천 지역, 맛집, 1일 일정이 담긴 리포트가 화면에 나와요
- 비밀번호·키 같은 비밀값이 코드와 기록에 남지 않았는지 확인하기 — AI와 지도 서비스의 열쇠는 .env 파일에만 두고, 그 파일은 올리지 않게 막아요(.gitignore). 올리기 전에 열쇠 글자가 코드에 남았는지 검사하고, 열쇠는 서버에서만 써요.

- ① 사용자가 여행 날짜를 넣고 버튼을 눌러요 → ② 앱이 가기 좋은 지역을 추천하고 그 지역 맛집을 찾아요 → 결과: 추천 지역, 맛집, 1일 일정이 담긴 리포트가 화면에 나와요 (고름)
- AI와 지도 서비스의 열쇠는 .env 파일에만 두고, 그 파일은 올리지 않게 막아요(.gitignore). 올리기 전에 열쇠 글자가 코드에 남았는지 검사하고, 열쇠는 서버에서만 써요. (고름)

## 5. 공부할 말

- 검증 기록 — 잰 값 — 실제로 재 본 숫자를 그대로 적어 둔 기록이에요
- 검증 기록 — 하지 못한 것 — 아직 못 잰 것을 숨기지 않고 '아직 못 함'으로 적어 둔 기록이에요
- 보안 점검 — 공개 전 인증 확인 — 앱을 열어 두기 전에, 허락된 사람만 들어오는지 확인하는 일이에요
- TDD — 확인 방법을 먼저 정하고, 그 확인을 통과하게 만드는 순서예요
- 단위 테스트 — 작은 부분 하나가 제대로 도는지 따로 확인하는 것이에요
- 수용 테스트 — 쓰는 사람 입장에서 처음부터 끝까지 써 보며 확인하는 것이에요
- 보안 점검 — 비밀값 검사 — 비밀번호나 열쇠 같은 값이 코드나 기록에 남지 않았는지 찾아보는 일이에요
